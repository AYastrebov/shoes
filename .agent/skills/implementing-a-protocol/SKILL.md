# Implementing a protocol

The root `AGENTS.md` rules apply throughout. This is the order of work.

## 1. Write the spec first

Anything larger than a bug fix gets `docs/specs/<date>-<topic>.md` before
code, in the shape of the most recent spec there: problem, scope, what the
reference implementations do with file-level citations, error handling,
testing, and an explicit list of what is out of scope.

## 2. Read the upstream source; do not recall it

Constants, byte layouts and framing rules go into the spec with the file
they came from. Memory is not a source:

- Salamander's constants were verified against `apernet/hysteria`,
  `extras/obfs/salamander.go`. They matched memory, but a wrong byte there is
  silent incompatibility with everything.
- TUIC's command layout and token derivation came from `EAimTY/tuic`,
  `SPEC.md`, which said two things memory would not have: the server never
  answers `Connect`, and heartbeats are sent only while a relay is in flight.
- TUIC's `quic` relay mode was fixed by reading `packet_quic` in
  `tuic-quinn/src/lib.rs`: one stream per fragment, each with a full header.

Most references are Go modules (`sing-box` and the `sing-*` libraries,
`xray-core`, `hysteria`, `mieru`, `amneziawg-go`); `go mod download
<module>@<version>` puts the source in the module cache (`go env GOMODCACHE`),
and `tests/data/kat/gen/go.mod` already pins the ones the vectors use. The
Rust references (`awgtun`, `tuic`) are pinned in `Cargo.toml`. Cite the
version you read.

Our own servers are authoritative for interoperating with us. The
specification is authoritative for interoperating with the world. When they
disagree, the specification wins and our server has a bug.

## 3. Pick the shape

- Most outbounds are a `SocketConnector` plus a `ProxyConnector`, so they
  compose into a chain.
- An outbound that owns its transport (WireGuard, AmneziaWG, Hysteria2,
  TUIC) implements `TerminalConnector` (`src/tcp/terminal_connector.rs`)
  and is always the last hop; `ClientProxyConfig::owns_transport()` routes
  it there. Add a new such protocol there rather than bending it into the
  chaining traits, and make validation reject it mid-chain, because the type
  system will not.
- The client and the server share one codec: `src/hysteria2/frame.rs`,
  `src/tuic/frame.rs`. Do not write a second copy for the other direction;
  if the server needs a different input shape, add a variant that shares the
  layout (`encode_packet_header_with_address` exists because the server has
  the address already serialized).
- Sessions and reuse: a hop that can reuse a live session answers
  `try_reuse_tcp_stream` on `TcpClientHandler` before the chain dials
  (`docs/specs/2026-10-19-session-reuse-without-dialling.md`).

## 4. QUIC transport parameters are part of the fingerprint

Copy the values our servers use (`src/quic_transport/`) rather than
inventing plausible ones; Hysteria pins its parameters as part of imitating
Chrome, so novel values are a signature that buys nothing.
`max_concurrent_uni_streams` must not be zero on a client: it bounds what the
server may open toward us, and HTTP/3 needs its control and QPACK streams
before Hysteria2's authentication can finish. Zero hangs instead of erroring.

## 5. Configuration

Follow `.agent/skills/adding-a-config-option/` for every new field: refuse
what is not implemented, validate what the reference validates with the
source named, document the field with its default, add a parsing example.
Say the things a user would otherwise learn painfully: a Hysteria2 password
is one opaque string, so a `userpass` server wants `<username>:<password>`;
a mismatched obfuscation password produces no error at all and looks exactly
like an unreachable server.

## 6. Tests

- End to end against this repository's own server, in-process
  (`src/quic_outbound/testing.rs`; see `src/vless/tests.rs`,
  `src/shadow_tls/tests.rs` and the Hysteria2 and TUIC client tests for the
  shape). Build the selector the way production does.
- Known-answer vectors from the reference's own computation go under
  `tests/data/kat/`, generated by the Go programs in `tests/data/kat/gen/`.
  Reference-captured first flights are replayed into the server
  (`src/reference_frames.rs`).
- A new server gets a row in the probe matrix (`src/probe_tests.rs`), which
  pins what it shows a client that is not one.
- Prove each new test can fail: plant the defect, confirm exactly that test
  goes red, restore.

## 7. Interop

Run the client against the reference server and our server against the
reference client before calling it done: `.agent/skills/live-interop-check/`.

## 8. Record

- `CHANGELOG.md` under `## Unreleased`, citing the audit or spec finding IDs.
- The audit table row, `ROADMAP.md` or `MOBILE.md` record the change in the
  same commit.
